================================================================================
                     VENDOROS - COMPLETE BACKEND API LIST & TESTING GUIDE
================================================================================
Base URL: http://localhost:3001
Content-Type: application/json

....Is file me Backend ki saari 80+ APIs (across 12 Modules, Phase 0 to Phase 7), unka kaam (Purpose), Headers, Testing ke liye 
Ready-to-use Dummy Data (JSON / Params) aur Expected Response formats diye gaye hain.

--------------------------------------------------------------------------------
AUTHENTICATION & HEADERS OVERVIEW:
--------------------------------------------------------------------------------
1. Public APIs (Register, Login, Verify OTP, Resend OTP): Kisi token ki zaroorat nahi hoti.
2. Protected APIs: 
   - Header: "Authorization: Bearer <YOUR_ACCESS_TOKEN>"
   - Ya phir browser/Postman me "accessToken" cookie automatically send hoti hai.
3. Multi-Tenant Business APIs (Categories, Products, Inventory, Sales, Payments, Customers):
   - Header: "x-business-id: <BUSINESS_ID>" (Optional agar user ke paas ek hi business hai, system auto-select kar leta hai).

10.1 SUPPLIER SCHEMA DB MODEL & MASTER ENTITY (T37)
--------------------------------------------------
Description: Defines the business-scoped Supplier master entity representing distributors, manufacturers, wholesalers, and stock vendors from whom the merchant procures inventory.

Schema Definition (`src/models/supplier.model.js`):
- `_id`: ObjectId (Primary Key)
- `businessId`: ObjectId (ref: 'Business', Required, Indexed)
- `company`: String (Required, Trimmed, Max 120 chars, e.g. "ABC Distributors")
- `contactName`: String (Trimmed, Max 100 chars, e.g. "Amit Sharma")
- `phone`: String (Canonical format e.g. "+919876543210")
- `email`: String (Trimmed, lowercase, Max 255 chars)
- `address`: String (Trimmed, warehouse/office address)
- `city`: String (Trimmed)
- `state`: String (Trimmed)
- `pincode`: String (Trimmed)
- `gstin`: String (Trimmed, uppercase, Max 20 chars)
- `currentBalance`: Number (Default 0.0, Materialized supplier payable outstanding)
- `totalPurchases`: Number (Default 0.0, Total procurement volume)
- `totalOrders`: Number (Default 0, Total purchase orders / stock-in receipts)
- `lastPurchaseDate`: Date (Default null)
- `lastPaymentDate`: Date (Default null)
- `status`: String (Enum: ['ACTIVE', 'INACTIVE', 'BLOCKED'], Default 'ACTIVE')
- `notes`: String (Trimmed)
- `tags`: Array of Strings (e.g. ['WHOLESALER', 'FMCG'])
- `timestamps`: true (createdAt, updatedAt)

Compound Indexes:
- `{ businessId: 1, phone: 1 }` (Unique, partialFilterExpression on non-empty phone)
- `{ businessId: 1, company: 1 }`
- `{ businessId: 1, currentBalance: -1 }`
- `{ businessId: 1, status: 1 }`
- `{ businessId: 1, createdAt: -1 }`

13. AUTO INVENTORY IN DEDUCTIONS / INFLOW ENGINE (PHASE 7 — T45)
================================================================================

13.1 OVERVIEW & ARCHITECTURAL CONTRACT
--------------------------------------------------
Task T45 automatically connects physical Goods Received Notes (GRN, T44) directly to active,
sellable inventory (T15) and immutable audit ledgers (T16) within an ACID MongoDB session.

Key Distinctions:
- T18: Generic manual stock IN (/api/inventory/stock-in) for adjustments, corrections, and opening stock.
- T45: Purchasing automated workflow service capability executing upon GRN completion.

3 Non-Negotiable Core Rules:
1. ONLY Newly Received Quantity Added:
   - For partial deliveries, only newly received quantities increment availableStock (never entire PO qty).
2. Idempotency & Duplicate Intake Prevention:
   - Queries `InventoryLedger.findOne({ businessId, referenceType: 'GRN', referenceId: grn._id, source: 'GOODS_RECEIPT' })`.
   - Rejects duplicate intake attempts with 409 DUPLICATE_GRN_STOCK_IN.
3. Strict Single-Transaction Boundary:
   - Executed via `withTransaction(async (session) => { ... })`:
     Create GRN -> Increment Inventory -> Insert InventoryLedger -> Update PO Line Items & Status.
   - Any failure triggers atomic rollback across all affected collections.

Internal Service Capabilities:
- `grnService.executeAutoInventoryIn(businessId, { grn, purchaseOrder, items, accountId, accountName, session })`
- `inventoryService.executeAutoInventoryInForGrn(businessId, options)`

Mathematical Ledger Invariant Maintained:
`Inventory.availableStock === sum(InventoryLedger.qtyChange)`
