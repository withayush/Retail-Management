1. DESIGN PHILOSOPHY & CORE PRINCIPLES
====================================================================================================

1. High Information Density with Zero Clutter:
   Retail environments require scanning dozens of products, stock levels, and transaction values
   simultaneously. Spacing and typography are optimized for compact readability without visual noise.

2. Pure Modern Dark Theme:
   Designed around a deep zinc backdrop (`#09090b` / `hsl(240, 10%, 4%)`) that reduces eye strain during
   long 12-hour cashier shifts and delivers a sleek, state-of-the-art aesthetic.

3. Instant Tactile Micro-Interactions:
   Every click, scan, and keypress provides instant feedback. Buttons compress subtly (`scale(0.975)`),
   modals pop using smooth spring bezier curves (`cubic-bezier(0.16, 1, 0.3, 1)`), and toasts confirm actions.

4. Tabular Financial Precision:
   Monetary amounts, quantities, SKUs, and barcodes always render with monospace / tabular numeral
   alignment (`font-mono` / `tabular-nums`) to prevent optical misalignment during rapid calculation.

5. Append-Only Ledger Visibility:
   Financial debits/credits and physical inventory additions/deductions are displayed with immutable,
   audit-transparent indicators (Running Balance, Transaction Type, Source, Timestamp, and Auditor).

6. Concurrency-Aware Feedback:
   In multi-terminal environments where stock and cash states change simultaneously, the UI communicates
   live inventory availability, locks expired transactions gracefully, and auto-syncs without data clobbering.

5. MOTION SYSTEM & SPRING ANIMATION CURVES
====================================================================================================

PHYSICS & TIMING CURVES:
- Spring Bezier : `cubic-bezier(0.16, 1, 0.3, 1)` (Snappy, natural pop without bouncy overshoot)
- Smooth Bezier : `cubic-bezier(0.4, 0, 0.2, 1)` (Subtle background and opacity fades)

ANIMATION PRESETS (Tailwind Keyframes):
1. `animate-fade-in`    : Opacity `0` -> `1` (0.2s)
2. `animate-slide-up`   : `translateY(8px)` -> `0px` + Opacity `0` -> `1` (0.25s)
3. `animate-modal-pop`  : `scale(0.96) translateY(6px)` -> `scale(1) translateY(0)` (0.25s)
4. `animate-slide-right`: `translateX(12px)` -> `0px` (0.3s)

INTERACTIVE MICRO-FEEDBACK:
```css
button:active:not(:disabled) {
  transform: scale(0.975);
}
```

8. CONCURRENCY-SAFE UI PATTERNS & STATE RESILIENCY
====================================================================================================

1. Prevention of Stale In-Memory State Overwrites:
   - All backend inventory mutations use atomic `$inc` operators. The UI reflects this by never caching
     quantities across stale tab instances.
   - Inventory audit adjustments auto-refetch the latest server state upon conflict rejections.

2. Atomic Sequential Identifiers:
   - Invoice IDs (`INV-1001`), Purchase Order IDs (`PO-1001`), and GRN IDs (`GRN-1001`) are backed by
     centralized MongoDB `$inc` counter sequences.
   - UI forms display generated numbers as immutable read-only badges to prevent duplicate key race conditions.

3. Credit Limit Enforcement Feedback:
   - In both POS Checkout and Settle Khata flows, customers exceeding credit limits are flagged with
     amber/rose warning callouts (`CREDIT_LIMIT_EXCEEDED`).
   - The UI disables credit checkout when customer has reached or exceeded their assigned credit limit.

====================================================================================================
9. FINANCIAL DATA INTEGRITY & AUDIT TRAIL STANDARDS
====================================================================================================

1. Mathematical Invariant Verification:
   - Customer Outstanding Balance = `Σ(Credit Sales) - Σ(Repayment Settlements) ± Adjustments`.
   - Supplier Accounts Payable    = `Σ(Purchase Deliveries) - Σ(Disbursements) ± Adjustments`.
   - Store Stock on Hand          = `Σ(Stock IN) - Σ(Stock OUT) ± Adjustments`.

2. Append-Only Financial Records:
   - Never provide "Edit" or "Delete" actions on past ledger entries.
   - Any financial reconciliation or inventory count correction must be initiated via an explicit
     `ADJUSTMENT` transaction with an audit reason tag and staff identification.

3. Debt Aging FIFO Calculation:
   - Debt aging in Customer 360° uses a First-In, First-Out (FIFO) algorithm against unpaid credit invoices.
   - Unpaid balances are chronologically bucketed into `0-30 Days`, `31-60 Days`, `61-90 Days`, and `90+ Days`.

10. USAGE RULES & DEVELOPER GUIDELINES
====================================================================================================

1. ALWAYS use the Tailwind HSL tokens (`bg-background`, `text-foreground`, `border-border`, `bg-card`).
   NEVER hardcode raw hex codes (e.g. avoid `#000000` or `#ffffff` in JSX components).
2. ALWAYS use `font-mono tabular-nums` when rendering currency (`₹`), quantities, SKUs, and barcodes.
3. ALWAYS provide visual active feedback (`active:scale-[0.975]`) on clickable action items.
4. Keep data tables responsive with horizontal scroll wrappers (`overflow-x-auto`).
5. Ensure all modals support dismissal via the `Esc` key and backdrop click.
6. Provide clear visual cues for loading (`animate-spin`), empty states (`PackageSearch`, `UserX`), and error toasts.
7. Use semantic toast notifications (`react-hot-toast`) with descriptive action feedback and duration >= 4000ms.
