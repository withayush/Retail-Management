--- [ PHASE 0 : AUTHENTICATION & SECURITY ] ---
[✓] A1. Registration (POST /api/auth/register)
    - Zod validation, strong password check, email & phone uniqueness check.
    - Bcrypt password hashing (10 rounds), Account created (PENDING_VERIFICATION).

[✓] A2. OTP Generation
    - Crypto-secure 6-digit OTP, bcrypt hash storage, 10-minute expiry.

[✓] A3. Phone OTP Verification (POST /api/auth/verify-phone)
    - Atomic DB Transaction: OTP consume + Account ACTIVE + Vendor auto-provision.

[✓] A4. Session & Dual Token Issuance
    - JWT Access (15m) + Refresh (7d) in secure HttpOnly cookies.
    - Session persisted in DB with hashed refresh token.

[✓] A5. Login (POST /api/auth/login)
    - Dual identifier: Email OR Mobile Phone login + Bcrypt verification.

[✓] A6. Phone Normalization (src/utils/phone.js)
    - Canonical `+91XXXXXXXXXX` conversion integrated across register, verify & login.

[✓] A7. Token Refresh & Reuse Detection (POST /api/auth/refresh)
    - Refresh Token Rotation (RTR). Stolen/reused token detection auto-revokes session.

[✓] A8. Logout (POST /api/auth/logout)
    - Inactivates DB session and clears client cookies.

[✓] A9. Protected Route & Auth Middleware (GET /api/auth/me)
    - Cookie-based JWT verification middleware.

[✓] A10. Database Schemas Defined (14 Models)
    - Account, OtpChallenge, Session, AuthLog, Vendor, Business, BusinessMember,
      Category, Product, Inventory, InventoryAlert, Invoice, Payment, Customer.

[✓] A11. Resend OTP API (POST /api/auth/resend-phone-otp)
    - Max 3 resend attempts limit, 60s cooldown check, update existing challenge with new OTP.

[✓] A12. Auth Attempts Logging (AuthAttempt Model)

[✓] A13. Pending Account UX Response
    - Return 403 `PHONE_VERIFICATION_REQUIRED` code with `phone` number for unverified user login.

[✓] A14. /me Profile Enrichment (GET /api/auth/me)

--- [ PHASE 1 : BUSINESS FOUNDATION & TENANT ISOLATION ] ---
[✓] B1. Business DB Schema Model (src/models/business.model.js)
    - Physical Business table structure with ID, businessName, retailSegment, ownerId (User ref), vendorId, address, currency, taxMode, inventoryTracking & status.
    - Designed as the core anchor linking User -> Business in a 1-to-many relationship (Multi-Tenant Isolation Foundation).

[✓] B2. Create Business API Endpoint (POST /api/business & POST /api/business/onboarding)
    - REST endpoint to register business details with model validations.
    - Sanitizes business metadata on creation (trimmed strings, phone/whatsapp canonical normalization, pincode format).
    - Expanded business segmentation: Grocery, Electronics, Clothing, Hardware, Pharmacy, Retail/Kirana, Kirana, Retail, Supermarket, FMCG, Wholesale, Service, Manufacturing, Other.
    - Configuration attributes: Currency (default 'INR'), Tax Mode ('GST', 'COMPOSITION', 'NON_GST', 'NONE', 'VAT'), Inventory Tracking (true/false).
    - Atomic lifecycle integration: Links User (ownerId) & Vendor, assigns OWNER role in BusinessMember, and auto-updates Vendor onboardingStatus to 'COMPLETED'.
    - Profile management: GET /me, GET /:id, PUT /:id with ownership access control.

[✓] B3. Get Business API Endpoint (GET /api/business/:id)
    - Fetches business configuration profile, settings, and contact details.
    - Integrates with user context middleware (`authMiddleware`) to verify access permissions (Owner / BusinessMember role).
    - Returns full business metadata + membership role context (OWNER/MANAGER/STAFF).

[✓] B4. Update Business API Endpoint (PUT /api/business/:id)
    - PUT /api/business/:id to modify operating hours, address, preferences, and profile settings.
    - Enables profile customization (operatingHours: open, close, days, notes, addressLine, city, state, pincode, currency, taxMode, inventoryTracking, logoUrl, status).
    - Enforces security to ensure only Owner can perform PUT (403 `ONLY_OWNER_CAN_UPDATE` rejection for non-owners).

[✓] B5. Business Setup Onboarding Wizard & Gate (GET /api/business/onboarding/status, POST /api/business/onboarding/step, POST /api/business/onboarding)
    - Step-by-step React/Next.js UI wizard workflow and onboarding gate before unlocking modules.
    - Step 1: Store Basics & Segment Selection (Grocery, Electronics, Clothing, Hardware, Pharmacy, Retail/Kirana, etc.).
    - Step 2: Location, 6-digit Pincode & Normalized Contact info.
    - Step 3: Setup Preferences (Currency 'INR', Tax Mode 'GST', Inventory Tracking 'ON', Operating Hours & Schedule).
    - Step-by-Step Draft State Tracking: Vendor model retains intermediate step progress and partial data so users can resume anytime without losing input.
    - Final Step Atomic Execution: On Step 3 completion (or 1-shot onboarding POST), automatically provisions the Business document, creates the OWNER BusinessMember record, marks Vendor `onboardingStatus = 'COMPLETED'`, and unlocks operational modules:
      [DASHBOARD, PRODUCTS, CATEGORIES, INVENTORY, INVOICES, CUSTOMERS, REPORTS].

[✓] B6. T6: User-Business Mapping Middleware (src/middlewares/business.middleware.js)
    - Essential security boundary attaching trusted active `req.businessId`, `req.business`, `req.businessRole`, and `req.businessMember` to all downstream requests.
    - Prevents cross-tenant data leakage between different businesses and profiles.
    - Supports `X-Business-Id` header with DB membership authorization checks (rejection with 403 `NO_ACCESS_TO_BUSINESS` for unauthorized access).
    - Auto-resolves default owned business when no header is supplied.
    - Includes `requireBusinessRole(["OWNER", "MANAGER"])` role-gating helper for protected operations.
    - Context inspection endpoint: `GET /api/business/active/context`.

--- [ PHASE 2 : INVENTORY & CATALOG CORE ] ---
[✓] C1. T7: Category Table Schema Model & Business-Scoped CRUD APIs (/api/categories)
    - Category Mongoose DB Model (`_id`, `name`, `description`, `businessId`, timestamps).
    - Multi-tenant Compound Unique Index: `{ businessId: 1, name: 1 }` (allows "Grocery" in different businesses, prevents duplicates in the same business).
    - Strict `businessId` tenancy isolation: `businessId` is ALWAYS derived from verified `req.businessId` (never trusted from request body).
    - Complete REST API Endpoints:
      - `POST /api/categories`: Create category for active business.
      - `GET /api/categories`: List all categories belonging to active business (with search filter).
      - `GET /api/categories/:id`: Get single category with tenant boundary check.
      - `PUT /api/categories/:id`: Update category with conflict check.
      - `DELETE /api/categories/:id`: Delete category within active business.

[✓] C2. T8: Product Schema DB Model & Business-Scoped Catalog APIs (/api/products)
    - Product Mongoose DB Model (`_id`, `businessId`, `categoryId`, `name`, `sku`, `barcode`, `sellingPrice`, `costPrice`, `unit`, `description`, `isActive`, timestamps).
    - Direct `businessId` tenancy isolation & Category ownership validation (blocks cross-business category injection with 400 `INVALID_CATEGORY`).
    - Multi-tenant Compound Unique Indexes:
      - `{ businessId: 1, sku: 1 }`: Scoped SKU uniqueness per business.
      - `{ businessId: 1, barcode: 1 }`: Scoped Barcode uniqueness per business.
    - Margin & COGS separation: Tracks `sellingPrice` and `costPrice` distinctly for accurate profit analytics.
    - Fast Barcode Scanner Lookup endpoint for POS billing machines (`GET /api/products/barcode/:barcode`).
    - Complete REST API Endpoints:
      - `POST /api/products`: Create product with SKU auto-uppercase & category ownership validation.
      - `GET /api/products`: List products with pagination, category filter & search.
      - `GET /api/products/barcode/:barcode`: Quick lookup by barcode for POS checkout.
      - `GET /api/products/:id`: Get single product by ID (Tenant isolated).
      - `PUT /api/products/:id`: Update product info and prices.
      - `DELETE /api/products/:id`: Delete product within active business.

4. CORE ARCHITECTURE & DATA FLOW
================================================================================

1. AUTHENTICATION, ONBOARDING & TENANT CONTEXT PIPELINE:
   [Client App]
         │
         ▼ (1. Register / Login)
   [Auth Routes] ──► [Auth Controller] ──► [Auth Service] ──► [Account & Otp Models]
         │
         ▼ (2. Verify Phone OTP)
   [Verify Controller] ──► [Vendor Model (onboardingStatus: PENDING, step: 1)] ──► Issue JWT Cookies
         │
         ▼ (3. Onboarding Wizard - Step 1, 2, 3)
   [POST /api/business/onboarding/step] ──► Validates Step Data & Saves Draft in Vendor Model
         │
         ▼ (4. On Step 3 Completion / POST /api/business/onboarding)
   [Business Service] ──► Creates [Business] + Creates [BusinessMember (OWNER)] + Marks [Vendor: COMPLETED]
         │
         ▼ (5. Tenant Isolation Layer - T6 Middleware)
   [businessMiddleware] ──► Validates Membership & Injects `req.businessId` + `req.businessRole`
         │
         ├──────────────────────────────────────────────────────┐
         ▼ (6. Category Management)                              ▼ (7. Product Catalog Management)
   [Category Routes (/api/categories)]                   [Product Routes (/api/products)]
   - Scoped strictly to `req.businessId`                  - Scoped strictly to `req.businessId`
                                                         - Validates Category belongs to same Business
                                                         - SKU & Barcode multi-tenant unique indexes
                                                         - Fast POS Barcode scan lookup endpoint

2. REQUEST-RESPONSE PATTERN:
   HTTP Request (with Cookies/JWT + optional X-Business-Id)
         │
         ▼
   `authMiddleware` (Verifies JWT + Validates active Account in DB -> req.user)
         │
         ▼
   `businessMiddleware` (Validates Membership -> Attaches trusted req.businessId)
         │
         ▼
   `validateRequest(schema)` (Zod sanitization & strict validation)
         │
         ▼
   `Controller Layer` (Uses req.user & req.businessId context)
         │
         ▼
   `Service Layer` (Executes business rules scoped to businessId)
         │
         ▼
   `Repository Layer` (Performs queries strictly isolated by businessId)
         │
         ▼
   MongoDB Database (14 interconnected CommonJS schemas)
