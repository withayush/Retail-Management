1. PROJECT OVERVIEW & CORE DESIGN PRINCIPLES
====================================================================================================
VendorOS is a high-speed, multi-tenant retail operating system engineered for physical kirana stores,
supermarkets, and retail chains. It addresses the high-speed requirements of cashiers at the billing
counter while maintaining strict mathematical consistency across inventory, ledger accounts, and customer debt.

CORE PRINCIPLES:
1. Multi-Tenant Tenancy Boundary:
   Every business entity (products, inventory, invoices, payments, khata) is strictly isolated by `businessId`.
   Zero cross-tenant data leakage is allowed.
2. Zero Data Loss & Historical Immutability:
   - Physical stock is NEVER overwritten directly; every movement is recorded in an immutable `InventoryLedger`.
   - Master catalog price updates apply only to future transactions; historical invoice line items are frozen.
   - Products are never hard-deleted from the database; soft-deletion preserves audit fidelity.
3. Atomic POS Checkout & Rollback Protection:
   Pre-flight stock verification prevents overselling. If any cart item is short in stock, the entire
   checkout transaction aborts without partial writes.
4. Keyboard-First Cashier Workflow:
   Cashiers can complete transactions using hardware barcode scanners and global function keys (F2, F4, F8, F9, Esc).

6. DATABASE SCHEMAS (16 MONGOOSE MODELS) & RELATIONSHIPS
====================================================================================================

1. `Account`: User credentials (`email`, `phone`, `passwordHash`, `status: ACTIVE | PENDING`).
2. `OtpChallenge`: 6-digit phone verification OTPs with 10-minute expiry and attempt limits.
3. `Session`: Stores active login session with hashed refresh token for RTR theft detection.
4. `AuthAttempt`: Audit log for tracking login attempts, IPs, and user agents.
5. `Vendor`: Vendor profile linked to `Account` with onboarding draft step state.
6. `Business`: Physical store anchor (`businessName`, `retailSegment`, `address`, `currency`, `taxMode`).
7. `BusinessMember`: Maps Users to Businesses with roles (`OWNER`, `MANAGER`, `STAFF`).
8. `Category`: Store categories with compound unique index `{ businessId: 1, name: 1 }`.
9. `Product`: Catalog items (`sellingPrice`, `costPrice`, `sku`, `barcode`, `unit`, `packSize`, `isActive`, `isArchived`).
   - Indexes: `{ businessId: 1, sku: 1 }`, `{ businessId: 1, barcode: 1 }`, text index on search fields.
10. `Inventory`: Current physical stock (`availableStock`, `reorderLevel`, `reservedStock`, `lowStockAlert`).
11. `InventoryLedger`: Immutable audit movements (`type: IN | OUT | ADJUST | OPENING | RETURN`, `qtyChange`, `balanceAfter`, `source`, `referenceNumber`).
12. `InventoryAlert`: Deterministic alert triggers (`severity: CRITICAL | WARNING`, `status: UNREAD | ACKNOWLEDGED | RESOLVED`).
13. `Invoice`: Sales transaction header (`invoiceNumber: INV-1001`, `grandTotal`, `paidAmount`, `balanceDue`, `paymentStatus`, `paymentMethod`).
14. `SaleItem`: Frozen checkout snapshots (`soldPrice`, `costPrice`, `quantity`, `totalPrice`, `grossProfit`).
15. `Payment`: Multi-tranche payments against invoices (`amount`, `paymentMethod: CASH | UPI | CARD | CREDIT | SPLIT`, `referenceId`).
16. `Customer`: Customer CRM profile (`name`, `phone`, `creditLimit`, `totalCredit`, `totalPaid`, `outstandingBalance`).
17. `CustomerLedger`: Immutable Khata statement (`type: SALE_CREDIT | PAYMENT_RECEIVED`, `amount`, `balanceBefore`, `balanceAfter`, `invoiceNumber`).

9. FRONTEND ARCHITECTURE, CUSTOM HOOKS & UI COMPONENTS (T30)
====================================================================================================

1. Hardware Barcode Scanner Hook (`useBarcodeScanner.js`):
   Listens globally for high-frequency keypress events (< 50ms interval). When a carriage return (`Enter`)
   is detected, it parses the accumulated buffer as a barcode, looks up the product via
   `GET /api/products/barcode/:barcode`, and pushes it directly into the active checkout cart.

2. Global Cashier Keyboard Manager (`usePOSKeyboard.js`):
   Provides zero-latency hotkey interception allowing cashiers to navigate the checkout terminal
   without touching the mouse.

3. Settle Payment Modal (`SettlePaymentModal.jsx`):
   Handles payment method selection (Cash, UPI, Card, Credit), partial payment splitting, live
   Udhaar calculations, and submits the atomic transaction payload.

4. Print Receipt Modal (`PrintReceiptModal.jsx`):
   Renders thermal-formatted 80mm/58mm printable receipts with store header, line item table, GST
   summaries, and payment details.

11. SECURITY, REFRESH TOKEN ROTATION (RTR) & SESSION MANAGEMENT
====================================================================================================

1. Dual-Token Model:
   - Access Token  : Short-lived (15 minutes). Sent in HttpOnly cookie or Authorization header.
   - Refresh Token : Long-lived (7 days). Stored in HttpOnly cookie and hashed in `Session` model.

2. Refresh Token Rotation (RTR):
   When `POST /api/auth/refresh` is called:
   - The presenting refresh token is validated against the active database session.
   - A new Access Token and a new Refresh Token are generated.
   - The session record is updated with the new refresh token hash.

3. Token Reuse & Theft Detection:
   If an old, previously rotated refresh token is presented again (indicating potential token theft),
   the system immediately terminates and revokes the entire user session, forcing a re-login.
